# parse/filter

Validated filter ASTs and parameterized PostgreSQL/SQLite query plans, including sort, keyset pagination, search, facets, and relation memberships. Use `parse.Resource` for the common struct-tag path; use these lower-level builders to integrate with existing SQL.

- Operators: `FilterOperator` and its `Op*` constants (`OpEq`, `OpILike`, `OpSome`, …: one per operator of the grammar, logical ones included), `Operators` (every operator a field may declare, in the documented order), `IsValidOperator` (one a field may declare), `ParseOperator` (the operator a JSON grammar key names, `"$gte"`)
- Parsing: `NewFilterParser` (`Parse`, `ParseBytes`, `ParseMap`, `And` — filters parsed apart, combined and bounded as one, `At` — the instant every relative-time token resolves against, which each parse otherwise reads once), `ParseSort`, `NewQueryParamParser` (`At`; refuses an accepted name the parser reads itself), `CheckAcceptedParam` and its `AcceptedParamError` (a parameter an endpoint means to read itself that is a list parameter or a flat filter on a field), `FlatParamFields`, `ResourceSchema.FlatParamField` (the field and operator a flat parameter filters), `ParsedFilter` (`AST`, a `FilterNode` tree; `EstimatedCost`, `ConditionCount`, `ParsedFor`: read through methods), `SortField` (one parsed sort key: a field and its `SortDirection`, `SortAsc` or `SortDesc`), `NewParsedFilter` (parsed for no schema: for evaluators and resolvers), `NewParsedFilterFor` (parsed for the schema its parser read, which a resource's builders check), `ResolveRelativeTime`
- SQL: `Dialect` (`Condition`, `ReadColumn`: how a statement reads a column of a declared `core.SQLType`, `DecimalValue` / `DecimalOrder`: a decimal operand (`DecimalColumn`, `DecimalMember` or `DecimalParam`, a `DecimalOperand`) as the dialect's exact decimal and as what orders it, each read from the operand itself; SQLite's call the functions `parsesqlite` registers); `TwoValuedCondition`: a rendering an index serves, exact where an even number of `$not`, usually none, enclose the condition; `MarshalValue`: a composite value bound as the driver takes it; `KeyIn` / `KeyOperand`: key columns of any scalar type as a row `IN` a set of keys bound as one parameter, each column compared as a filter compares its type, the comparison relation joins, key sets, includes, facets, memberships and `patch.RenderRelationOp` share; `StoredKeyValue`: a key value as the database holds it, a PostgreSQL timestamp at microseconds; the SQL a patch writes, each method documented where `patch.SQLDialect` and `patch.RelationDialect` consume it (`ChangedCondition`, `ChangedDocumentCondition`, `MergePatch`, `ArrayAppend`, `MemberDocument`, `SetMember`, `RemoveMember`, `HasMember`, `IsObject`, `RelationRows`); `StoresAsText`: the values the database stores as text a row scan decodes, a timestamp's canonical text or a document's or an array's JSON (`parse.RowScanner`, which refuses a dialect that reports another type). Every piece of SQL whose form differs between databases is a method, so a new SQL provider is one type implementing `Dialect`. The two dialects are the only ones, and the set is sealed: `Dialect` has unexported methods, its element table, facet keys and search among them, and a type that embeds one of the two to override a method is not a dialect parse supports, since the built-in methods call their own receiver's), `PostgresDialect` (`ContainmentMaxValues`, `DefaultContainmentMaxValues`), `SQLiteDialect`, `DialectFromDSN` (decided by the DSN's form alone: PostgreSQL for a `postgres://` or `postgresql://` URL, a CockroachDB cluster's included; SQLite for a `sqlite://` or `sqlite3://` URL, a `file:` URI, `:memory:`, or an absolute, `./` or `../` path to a `.db`, `.sqlite` or `.sqlite3` file; a form other drivers' DSNs take is `ErrUnknownDSN`, whose message names the scheme and never the DSN: CockroachDB's `cockroach://` and `crdb://`, a bare `app.db`, which keyword/value, MySQL and Oracle DSNs also end as, `//host/…` and a one-segment `/name.db`. A form is evidence, not proof: another driver's DSN in an accepted form gets that form's dialect), `NewSQLBuilder`, `SQLResult` (`Where` is a selection predicate), `AndSearch`. A `$in` / `$nin` set binds as one parameter whatever its size

- Facets / includes: `FacetRequest` (a field to count and its optional limit), `FacetType` (`FacetTerms`, `FacetTypeRange`), `FacetRange` (a range bucket's bounds), `FacetQuery` (the statement and its arguments), `FacetResult` (one field's buckets), `BuildFacetQueryOption`, `IncludeQueryOption`, `DefaultMaxIncludePerRelation` (the ids an include carries per owner when the relation sets no cap); `BuildFacetQuery` (refuses a facet generation would: terms on a type with no common key, range off a number field, malformed ranges; rows in a fixed order: request order; terms by count, ties by value for numbers and by code point otherwise; ranges as declared; declared relations count visible related keys; `WithFacetFrom` reads the rows of an aliased table or a join), `ScanFacetUnion`, `FacetMap` (results keyed by field, as `Page.Facets` carries them), `FacetKeys` (a value's bucket keys, its canonical text, for a backend counting in Go), `FacetBuckets` (that order for a backend counting in Go, given the field; a list facet counts each distinct element once per row), `ParseFacetTag` (a terms limit of at least 1, uncapped; finite, half-open, disjoint ranges), `ParseIncludes`, `BuildIncludeQuery` (declared relations read visible related rows; text keys use code-point order before deduplication/capping; `WithIncludeOwner` for a row tenant), `IncludeQuery.Scan` → `IncludeRows` (IDs, owners `Truncated` at the cap), `ResolveInclude` / `IncludeLookup` (the same projection outside SQL through batched owner/target pairs, `LookupPairs` projecting the owner's key columns beside the lookup's), `Page.SetInclude` (canonical page projection; empty results omitted), `MaxIncludes`, `Rows`
- Policy: `ErrPolicyInvalid` (a policy the schema cannot compile, a plain error and never a `*core.ParseError`: policy is the server's), `PolicyConstraints` (`Merge`), `PolicyConstraint` (`Fields`: a key constraint over a key's columns, one `core.Key` under `OpEq`, a set of them under `OpIn` compiled to `OpKeyIn` over a `KeySet` and bound as one row-value parameter, an empty set admitting no row; a key of several columns names stored columns only, and a computed one (`ResourceSchema.Computed`) is `ErrPolicyInvalid`; `UnknownIfInvalid`: a value that does not apply to the field compiles to SQL's unknown — no row satisfies it, nor its negation — instead of an error), `UnknownConstraint` (that unknown, stated), `ApplyPolicyConstraints` (values normalized as request values, without request limits, each Go value — an operand, a set's member, a key's position — first read as the database holds it, `core.StoredValue`, so a `driver.Valuer` stands for the value it writes; `ResourceSchema.PolicyFields` holds those requests never reach), `ErrAmbiguousPolicyField` (a name that designates more than one field, whichever is declared first; a field a filter field could not type returns its own error instead — [policy fields](../docs/queries.md#policy-fields)), `BuildBaseConstraints` (the tenant in the tenant column's type; ## Build, run and test

From the module directory (`parse/`):

```bash
go test -tags=unit ./filter/...                         # parser, SQL builders, Evaluate, the conformance families in memory
go test -tags=integration ./filter/...                  # the same on SQLite; PostgreSQL and PostGIS with PARSE_POSTGRES_DSN / PARSE_POSTGIS_DSN
go test -tags=unit -run '^$' -fuzz FuzzParseThenBuild ./filter   # parse arbitrary filters and build each on every dialect
```

## Operations

filter parses requests and builds SQL with its arguments; it runs no statement, so it holds no connection and has no health check, metrics or logs of its own. Its failures:

- A `*core.ParseError` is the request's fault, with its code ([error catalog](../docs/http-errors.md#error-codes)). A filter's estimated cost is checked against `MaxCost` before SQL is built (E2061); [query costs](../docs/operations.md#query-costs-and-limits) explains the estimate.
- `DecodeCursor` answers E2082 with one of two messages. `unsupported cursor version` is a well-formed cursor of another generation, minted by another release during a rolling deploy or held by a client across one; the client starts again from the first page, and the server has nothing to fix. `invalid cursor data` is a malformed or altered token ([cursor generations](../docs/queries.md#lists-and-keyset-pagination)).
- A sentinel error is the server's, raised by a builder: `ErrRelationTenantRequired` (a tenant-scoped relation table joined or looked up with no tenant: bind one, or opt out with `RelationScope.Unscoped`), `ErrRelationUnresolvable` (a relation declared or wired so it cannot be evaluated: no target resource or target key field, a declaration that does not check, no membership or include lookup outside SQL, a lookup that is no `RelationLookup` for a target filter, a relation `Evaluate` meets unresolved, or a key comparison only SQL evaluates), `ErrRelatedPolicyRequired` (a policy-scoped relation built without its target's policy in `RelationScope.Related`), `ErrPolicyInvalid` (a policy constraint the schema cannot compile), `ErrAmbiguousPolicyField` (a policy constraint whose field names more than one field), `ErrUnsupportedDialect`. Match them with `errors.Is`; none is the client's to fix.

## Security

SQL identifiers come only from the schema and are quoted by the dialect; a request's field names are looked up in the schema, and its values bind as parameters. A `FieldSchema.Expr` and a computed column are trusted application SQL. A server policy (`ListPolicy`, `Scope`) is ANDed with the request's filter, so a request narrows what the server admits and never widens it; tenant-scoped relations refuse to build without a tenant. A cursor is a position, not a permission: authorization and tenant scope apply to every page. See [trust boundaries](../docs/operations.md#trust-boundaries).
