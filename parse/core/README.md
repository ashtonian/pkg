# parse/core

Configuration, schema generation, value normalization, JSON Pointers, and errors shared by the parser packages. Use this package to configure a typed parser or implement a custom schema adapter.

## Usage and configuration

| Guide | Contents |
|---|---|
| [Schema, tags, options, and value model](../docs/schema-configuration.md) | Consumer guide |
| [Error handling and codes](../docs/http-errors.md) | Consumer guide |

A parser is configured by a `ParserConfig` built from `Option`s, and a schema generator by `GeneratorOption`s; both are tabled with their defaults in [parser and generator options](../docs/schema-configuration.md#parser-and-generator-options).

Start with the [runnable package example](../README.md#quick-start). The focused [core example](example_test.go) is compiled and output-checked in the unit suite.

## API reference

- Config: `DefaultConfig`, `ParserConfig` (one rule for its limits: zero is the default for depth, cost, conditions and array size, zero or less is unlimited for input size and copy bytes, zero derives the list body size), `Option`, `(*ParserConfig).Effective` (the configuration every filter and patch parser reads, defaults filled in; nil is `DefaultConfig`), `(*ParserConfig).Validate` (refuses a negative limit, naming the option), `(*ParserConfig).GetCodec`, `(*ParserConfig).ListBodyLimit` (the bound a POST list body takes: `MaxListBodySize`, or one derived from `MaxInputSize`; nil-safe), `(*ParserConfig).PatchBodyLimit` (the bound a patch body takes: `MaxInputSize`, or 1 MiB when it is unlimited; nil-safe), and the options `WithMaxDepth`, `WithMaxCost`, `WithMaxInputSize`, `WithMaxListBodySize`, `WithMaxConditions`, `WithMaxArraySize`, `WithMaxPatchCopyBytes`, `WithGeneratorOptions`, `WithClock`, `WithCodec` ([options and defaults](../docs/schema-configuration.md))
- Generation: `NewSchemaGenerator`, `SchemaGenerator` (`TableName`, `MappedExpr`, `ColumnName`, `FieldColumn`, `FieldNameTag`, `ColumnTagKey`, `StructFields`; its options are copied at construction and read through `DefaultFilterOps`, `DefaultPatchOps`, `SortMaxFields`, `SearchParam`, `SearchLanguage`, `MapsColumns`), `JSONTagKey` (the tag encoding/json names members by; the default field-name tag), `DefaultColumnTagKey`, `GeneratorOptions`, `GeneratorOption` (`WithSQLTableName`, `WithColumnTypes`, `WithColumnMapper`, `WithColumnConvention`, `WithTableConvention`, `WithFieldNameTag`, `WithColumnTag`, `WithSortMaxFields`, `WithSearchParam`, `WithSearchLanguage`, `WithForeignTagKeys`), `SQLColumnMapper`, `NamingConvention` (`SnakeCase`, the default, `CamelCase`, `PascalCase`, `LowerCase`), `TableConvention` (`PluralSnake`, the default, `Singular`, `PluralCamel`)
- Types: `FieldType` (the `FieldType*` constants, `FieldTypeString` … `FieldTypeGeo`), `SQLType` (`SQLInet`, `SQLCIDR`, `SQLInterval` and their arrays `SQLInetArray`, `SQLCIDRArray`, `SQLIntervalArray`: database types a resource declares for its dialect to read as text; `Valid`, `IsArray`, `IsJSON`), `IsValueType` / `CheckValueStorage` / `ImpliedSQLType` (the declarations a value type's column takes), `TypeOf` (a column's type: a nullable wrapper is its value's), `MemberTypeOf` (a document member's), `NullWrapper` / `NullWrapperOf` (a struct of a value and a `Valid bool` whose zero value is NULL; a column of one is its value's type, so it may be a key or tenant column as a pointer may. A struct with any other field is no wrapper: pgtype.Timestamptz, with its InfinityModifier, stays an object. A wrapper's value is typed as itself: pgtype.UUID's bare `[16]byte` is binary, not a UUID), `TypeInfo`, `IsDocument`, `NumericKind`, `IsNullableType` (whether a field of the type holds NULL: a pointer, slice, map or interface, or a type whose zero value accepts `Scan(nil)` and then reports `Value() == nil`, such as `sql.NullInt64`; a UUID or decimal type, though an `sql.Scanner`, is not — the one rule sort keys, the soft-delete column and patch paths share), `IsUUIDType` / `UUIDText` (any UUID type: a named 16-byte array whose zero value writes the nil UUID's text), `Decimal` / `IsDecimalType` (any decimal type with the `Coefficient` / `Exponent` method set, recognized by shape), `CustomJSON` / `MarshalsJSON` (a type that codes itself as JSON through encoding/json or encoding/json/v2 methods on T or *T: the one test every reader of a document applies)
- Value types, each with one canonical text in JSON, text, SQL parameters and cursors: `Date` / `ParseDate`, `LocalTime` / `ParseLocalTime`, `Interval` / `ParseInterval`, `Inet` / `ParseInet` / `InetFromAddr` / `InetFromPrefix`, `CIDR` / `ParseCIDR` / `CIDRFromPrefix`, `MACAddr` / `ParseMACAddr`
- Order: `CompareCanonical` (two values of a column's type in the order the SQL dialects give it: NULL last, numbers and decimals by value, a float column's NaN after `+Inf` and equal to NaN, as PostgreSQL orders float8, a decimal column's `NaN` and infinity texts as it orders numeric, a float32 column's finite values at float32 precision, strings by code point, other text types by canonical text, false before true; a value the type cannot hold, a float's NaN outside a float column or an unordered type is an error; the one order filters, keysets, keys, patch policies and untyped lookups compare by), `CompareCanonicalTexts` (two canonical texts in that order: numbers by value, other types by code point; a terms facet's ties), `TextOrdered` (whether a type's canonical texts order by code point as its values do: every key type's but a number's, so a walk may compare them as text)
- Stored values: `StoredValue` (the value the database holds for a Go value, and whether it is NULL: pointers followed, a `driver.Valuer` read, a type parse types by its Go type kept as it is; the one reduction cursors, facets, memberships and relation keys share), `Deref` (pointers and interfaces followed, nil for a nil one; more than 32 in a chain, such as a `*any` holding itself, is an error, and so is it for every reader below that follows them)
- Values: `NormalizeInt`, `NormalizeUint`, `NormalizeFloat`, `NormalizeScalar` (a named string read as the string it holds for every type a string spells), `NormalizeStored` (a stored value: `NormalizeScalar`, a float column's NaN and infinities kept, and a decimal column's as `numeric`'s text, a bool column's 0 and 1 read as SQLite stores them), `NonFinite` (a stored float's or decimal's NaN or infinity), `StoredScalar` (a row's value as a driver scans it, in its column's canonical form: `StoredValue`, then `NormalizeStored`; NULL is absent), `StorageValue` (a Go value in the one form a row stores it, which SQLite's dialect binds and a store holding rows itself keeps: NULL for nil, a nil pointer or a nil array; a date and a timestamp as their canonical text; a document or an array as its JSON text, each element of a list of timestamps canonical; a `driver.Valuer` as the value it writes unless the column declares JSON; anything else as its `driver.Value`), `NormalizeJSON`, `JSONEqual` (document equality as jsonb compares), `CompareNumbers`, `IsNumber`, `DecimalText` / `CompareDecimals` / `MaxDecimalDigits` (canonical exact decimal text and its order), `PortableDecimal` (a JSON number literal every backend compares as the same value), `AnySlice`, `FormatTimestamp` / `TimestampLayout` (canonical timestamp text: UTC, nine fractional digits, fixed width), `MicrosecondTimestamp` (that text as a PostgreSQL `TIMESTAMPTZ` column holds it: rounded to the microsecond as PostgreSQL rounds, ties to even), `CheckText` / `CheckValueText` / `ErrInvalidText` (request text holding U+0000 or invalid UTF-8, which no backend compares as written, refused where request values are read — `CheckValueText` reaches every string of a normalized value, member names included; stored values are not checked)
- Pointers: `ParsePointer`, `FormatPointer`, `EscapePointerToken`
- Relations: `RelationSchema` (`SourceColumns`, `TargetColumns`, `OwnerKey` and `TargetKeys`: column lists that pair by position, one column each for a one-column key; `SourceTypes` and `TargetTypes`: the scalar type of each source and target column, which every statement compares it as; `OwnerColumns`: its `OwnerKey`, or `DefaultPrimaryKey` alone; `Check`: refuses lists that cannot pair and columns not typed by a scalar, naming them; `Clone`; `RelatedTable`: the table its nested predicates test), `PairRows` and `PairTenant` (what a SQL dialect's `RelationRows` hands a relation insert without a target table: the expressions its select list writes each pair column from, its FROM clause and conditions, and the tenant every pair is written for), `RelationKind` (`ManyToMany`, the zero kind, `HasMany`, `BelongsTo`), `DefaultPrimaryKey` (`"id"`, a resource's or relation owner's key when none is declared), `ParseRelationTag` (a key's columns joined with `+`; its columns untyped), `SchemaGenerator.RelationTag` (a field's tag, its source columns typed by the struct's fields holding the owner key and its target by the slice's element, or, for a target key of several columns, by the element struct's fields holding them: `SchemaGenerator.RelationTargetFields`), `IsIdentifier`
- Keys: `Key` (a row's key: a value per key column, in key order), `NormalizeKey` (the one key rule: a value per column, each read as the database holds it and normalized as its column's type; the root package's targets, owners and parsed keys, patch's relation keys and filter's key sets all bind through it), `KeyValueError` (the position of the value `NormalizeKey` refused), `KeyText` (a key's text, as includes and facets name a row: a one-column key's value, a longer key's compact JSON array of its values' texts, which PostgreSQL's `array_to_json` and SQLite's `json_array` write for the same row), `KeyTextOf` / `CanonicalText` (a key's, or one value's, canonical text, each value normalized as its column's type: equal exactly when the database holds two keys equal, and the text includes, facets and typed lookups name a value by), `IsKeyType` (a scalar: the types a key, a relation's columns and a membership compare; a document, array, geometry or opaque value is none)
- Errors: `Code` and its constants `Code*` (`CodeUnknownField` = E2071, …: each code's one definition, with its status and default message; filter, patch and parse alias them as `ECode*`), `Codes` (the table, sorted: the catalog), `ParseError` (`ErrorCode`, `ErrorMessage`, `ErrorHTTPStatus`, `IsErrorUserFacing`), built only by `NewError(code, message, opts...)` and its `ErrorOption`s: `WithPath` (the patch member's JSON Pointer, and the field it names), `WithIndex` (the JSON Patch operation's position), `WithField`, `WithParameter`, `WithDetail` (any other `Details` key) and `WithCause`; `DetailField` / `DetailParameter` (the `Details` keys; `Details` is absent until an option sets an entry). `Details[DetailField]` follows the field rule below
- Documents: `JSONFieldsOf` (a struct type's members as encoding/json names them, no other tag read; a type that codes itself as JSON still has its fields named; the module's internal key validation of stored documents names members the same way, through `internal/shapes`)
- Fields: `StructFieldsOf`, `StructFields` (`Type`, `Len`, `Fields`: an iterator in declaration order, `External`, `ColumnTagged`, `FoldedMatch`: the field encoding/json decodes a member into by case folding), `Field` (`GoName`, `Type`, `Route`, `External`, `Tags`, `Enum`, `Bounds`, `Value`, `Settable`, `SettableThrough`: `Settable` with the caller pointing each embedded pointer on the route, as the patch applier points it at a copy it owns, `CheckWritable`: refuses a field promoted through an unexported embedded pointer, which neither a row scan filling a fresh row nor a writer that must not write the caller's parent can set, `Hidden`, `RelationName`: the name filters and patches both address a relation field by, `HasFieldNameOption`, `Quoted`, `Wire`), `Tags`, `Capabilities` (`Has`), `Capability` (the `Capability*` constants, `CapabilityFilter`, … — the `parse` tag's values, which the `paths` tag's member capabilities share), `Bounds` (`IsZero`, `BoundsValues`, `CountsItems`, `Check`: a field's `minlen` / `maxlen` / `min` / `max` / `minitems` / `maxitems`, the tags the `Constraint*` constants name) — one walk of a struct type shared by every schema; `ParseEnumTag` (an `enum` tag's values: comma-separated, or single-quoted to hold a comma, a leading or trailing space or an empty value), `EnumAllows` (whether a value is one of them, compared exactly: the one rule filter and patch both apply)
- Codec: `Codec`, `StdlibJSON`; naming: `Pluralize`; the declared-constraint names `Constraint*` (`ConstraintEnum`, …), which `patch.ConstraintError` reports

The field rule: `Details[DetailField]` names the one field an error is about, as the request named it — a filter or sort key as written (a dotted document path whole; a key of a relation predicate's or a document array's element filter by its name there; a scalar array's element condition by the array's name), an include, facet or response-field name, a relation field, and for a patch operation the resource field its path's first token names, while `Path` keeps the whole pointer. `WithPath` sets both, so a patch error with a path names its field; a path that is no valid pointer, the whole document, or a first token that is not valid text (`CheckText`) names none. An error about a field's name, operator or value names the field, and so does one about the shape or size of what the request gave that field (an `$in` that is no array or holds too many members, a document nested too deep, a geo operand, a relation predicate nested too deep). Errors about the request as a whole name none: body size, JSON syntax and the shape of `$and` / `$or` / `$not` above any field, filter nesting depth, cost and condition counts, operation and sort-key counts, a cursor, the copy budget, a schema lookup, and a JSON Patch operation refused before its path is read, which `Index` alone names. A list parameter is `Details[DetailParameter]` instead. The root package's unit suite holds every code to the rule and refuses a `ParseError` composite literal outside core (`errors_internal_test.go`).

A field walk (`StructFieldsOf`, `JSONFieldsOf`, `SchemaGenerator.StructFields`) is compiled once per struct type and tag pair and shared by every generator, resource and stored-document check in the process, so it is read-only. Types are finite and never unloaded, so the walk caches are unbounded: each holds one entry per type it has been asked for. A `*StructFields` and each `*Field` it yields are shared handles; what their methods return is either another shared handle or a value the caller owns. `Route`, `Enum` and `Bounds` allocate the caller a copy (`Enum` and `Bounds` only for a field that declares them); `Tags` is a plain value with no references, so the copy `Field.Tags` returns is the caller's; and `slices.Collect(walk.Fields())` gives the caller its own slice. `Fields`, `Len`, `External`, `ColumnTagged`, `FoldedMatch`, `Tags`, `Value`, `Settable` and the other accessors allocate nothing: per-request lookups by name and column are map reads on the shared walk.

## Build, run and test

From the module directory (`parse/`):

```bash
go test -tags=unit ./core/...          # normalization, generation, pointers, codes; the core example
go test -tags=unit -race ./core/...    # as the nightly run does
```

## Operations

core does no I/O and starts no goroutines, so it has no health check, metrics or logs of its own. Its failures are values:

- A `*core.ParseError` is the request's fault: `Code` names it, `ErrorHTTPStatus()` gives its status and `Message` is written for the client. Every code is in the [error catalog](../docs/http-errors.md#error-codes).
- A plain error from schema generation or `(*ParserConfig).Validate` is the server's configuration, raised at startup by `NewResource` or the generator, naming the field or option to fix.
- Every request is bounded by the [parser limits](../docs/schema-configuration.md#parser-and-generator-options); one over a limit is refused with its code (E2061, E2063, E2074, E2088, E2089), never parsed in part.

## Security

Struct tags, column mappers, naming conventions and `WithColumnTypes` are trusted server configuration: they name the tables and columns SQL is built from, and generation refuses a name that is not an identifier. Request text is untrusted and reaches the parsers only through the limits above. `Code.IsErrorUserFacing` reports whether a code's message may be shown to a client.

Civil calendar values use `Date` / `ParseDate` and `FieldTypeDate`, distinct from timestamps. JSON, text, SQL parameters and cursors use exactly `YYYY-MM-DD`; invalid dates, instant strings and a non-nullable zero/null value fail. Use `*Date` for nullable storage. `date.go` implements validation, atomic decoding and SQL scanning/values without applying a viewing timezone; the [schema guide](../docs/schema-configuration.md#civil-dates) covers resource declarations.

`LocalTime`, `Interval`, `Inet`, `CIDR` and `MACAddr` follow `Date`'s shape for SQL TIME, INTERVAL, INET, CIDR and MACADDR: `FieldTypeTime`, `FieldTypeInterval`, `FieldTypeInet`, `FieldTypeCIDR` and `FieldTypeMACAddr`. Each reads its accepted input forms, holds and writes one canonical text, and scans the text PostgreSQL, pgx and SQLite return. The [schema guide](../docs/schema-configuration.md#time-interval-and-network-values) lists each grammar and the filters each type offers.
